# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- Build: `dotnet build`
- Run the API: `dotnet run --project src/OrderManagement.Api` (needs MySQL and user-secrets, see README)
- Docker stack: `docker compose up --build` (copy `.env.example` to `.env` first)
- All tests: `dotnet test` (integration tests need Docker running)
- One test: `dotnet test --project tests/OrderManagement.UnitTests --filter "FullyQualifiedName~<Name>"`. The runner is Microsoft.Testing.Platform (`global.json`); without `--project`, a project with no match makes the run exit with code 8.
- Regenerate the EF model after a schema change: `scripts/scaffold.ps1` (needs Docker and the local `dotnet-ef` tool).
- On an old Docker Engine (20.10), integration tests need `DOCKER_API_VERSION=1.41` in the environment. Never commit that setting.

## Architecture

.NET 10. `src/` has Domain, Application, Infrastructure and Api; `tests/` has UnitTests and IntegrationTests.

- Dependencies point inwards: `Api -> Application, Infrastructure`; `Infrastructure -> Application, Domain`; `Application -> Domain`. Domain has no package references and never reads the clock (time arrives as `DateTime utcNow`).
- Application holds services, DTOs, FluentValidation validators and the interfaces (repositories, `IUnitOfWork`, `ICurrentUser`). Infrastructure implements them with EF Core (`MySql.EntityFrameworkCore`), DbUp, JWT and the password hasher.
- Package versions are central in `Directory.Packages.props`. No AutoMapper, MediatR or FluentAssertions (licensing); mapping is by hand.
- Config keys: `ConnectionStrings:Default`, `Jwt:*` (signing key at least 32 bytes), `Seed:*`, `Cors:AllowedOrigins` (empty in base settings; `http://localhost:4200` in Development/Docker; `UseCors` runs before the exception handler so error responses keep their CORS headers). Secrets come from user-secrets (Development) or `.env` (Docker); `appsettings.json` holds none. `Program.cs` runs DbUp and the seeder only in `Development` and `Docker`; the `Testing` environment leaves that to the tests.

## Database-first rules

- SQL scripts in `database/migrations/NNNN_*.sql` are the source of truth. Never edit a committed script; add a new one.
- Entities and `AppDbContext` are generated (they carry an `<auto-generated>` header). Never hand-edit them; run `scripts/scaffold.ps1`. The customized templates are in `Infrastructure/CodeTemplates/EFCore`.
- Business rules go in `<Entity>.Behavior.cs` partials. Services change entities only through behavior methods, never by setting generated properties. `AppDbContext.Partial.cs` holds the concurrency token (`Product.StockQuantity`) and `IUnitOfWork`.
- A new table must also be added to the `--table` list in `scripts/scaffold.ps1`, or it is silently left out of the model.
- Commit a new script and the regenerated code together.
- IDs are `Guid.CreateVersion7()`, money is `decimal(18,2)`, times are UTC.

## Error handling

`GlobalExceptionHandler` turns exceptions into RFC 9457 ProblemDetails with a `traceId`:

- validation failures (from `ValidationFilter`): 400 with per-field `errors`
- `NotFoundException`: 404; `ConflictException`: 409 (Infrastructure maps `DbUpdateConcurrencyException` and MySQL duplicate key 1062 to it)
- any other `DomainException`: 400
- anything else: 500 with a generic message

Empty 401/403/404 responses also become ProblemDetails through `UseStatusCodePages`. A customer asking for another customer's order gets 404, not 403.

## Assistant (LLM tool calling)

- `POST /api/v1/assistant/chat` (CustomerOnly). The loop and the gate are in `Application/Assistant` (`AssistantService`, `ToolExecutor`, `Tools/`). Provider SDKs live only in `Infrastructure/Assistant`, behind `IAssistantModel`.
- **One adapter for every provider:** `ChatClientAssistantModel` implements `IAssistantModel` on `Microsoft.Extensions.AI`'s `IChatClient`. `ChatClientFactory` builds the client for `Assistant:Provider` (`Claude`, `OpenAI`, `Gemini`, `Ollama`) and returns null when that provider has no key or endpoint (the endpoint then answers 503). Tools are sent as declaration-only functions and the client is never wrapped in `FunctionInvokingChatClient`: a tool runs only through `ToolExecutor`.
- Model input is untrusted. Tools take no user ID, customer ID or role. They call services that read the caller from `ICurrentUser`, and every call goes through `ToolExecutor` (allowlist, then strict input validation, then a restricted DTO). Never return entities or full response DTOs to the model.
- To add a tool: implement `IAssistantTool` with a JSON schema (`additionalProperties: false`), validate the input with `ToolInput`, return a small result record, register it in `AddApplication()`, and add unit tests plus a cross-customer integration test.
- To add a provider: add an `AssistantProvider` value and options section, a `ChatClientFactory` case, a `ProviderErrors` rule for its exception types (put provider-specific types before the generic `HttpRequestException` case: Google's derive from it), and a stub-server test in `ProviderRoundTripTests`.
- Keys come from configuration/environment (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY`); Ollama uses `Assistant:Ollama:Endpoint`. Settings are in the `Assistant` section. The OpenAI and Gemini default model names are unverified.
- Tests never call a provider. Unit tests use `FakeAssistantModel` and `ScriptedChatClient`, adapter tests use `StubApiServer` (a local HTTP server, so these unit tests do loopback I/O), and API tests script `ApiFactory.Assistant` (`ScriptedAssistantModel`). To check logging, swap `ILogger<T>` through DI with `CapturingLoggerProvider.For<T>()`: the app logs through Serilog, which ignores providers added to the host.

## Policy Q&A (RAG)

- `POST /api/v1/policies/ask` (any signed-in user) and `POST /api/v1/policies/reindex` (AdminOnly). Policy retrieval is separate from orders: nothing in this feature reads order data, and it never will.
- **Pure vs I/O:** `Application/Policies` has no file, HTTP or Qdrant types. It holds the chunker, BM25, rank fusion, `PolicyIndexer`, `PolicyRetriever`, `PolicyPrompt`, `PolicyQuestionService` and the ports (`PolicyContracts.cs`). `Infrastructure/Policies` implements them: `MarkdownPolicyLoader`, `OllamaPolicyEmbedder` (Qwen3 query prefix `Instruct: ...\nQuery: ...`, documents unprefixed), `QdrantPolicyVectorStore`, `PolicyAnswerGenerator` (the `Assistant:Provider` chat client, no tools) and `PolicyIndexingHostedService` (startup index, `Development`/`Docker` only, never blocks startup). `AddPolicies()` and `AddPolicyInfrastructure()` are called from `AddApplication()` / `AddInfrastructure()`.
- **No duplicates on re-index:** the chunk ID is a GUID from SHA-256 of `source|headingPath|part`, so an upsert replaces. The fingerprint stored as `content_hash` is `SHA-256(embeddingModel|text hash)`; only added or changed chunks are embedded, and IDs not in the new set are deleted. `PolicyIndexer` rebuilds the in-memory BM25 index first, so keyword search survives an Ollama or Qdrant failure, and a semaphore allows one re-index at a time.
- **Grounding:** the prompt numbers the excerpts and wraps the question in `<<<QUESTION ... QUESTION>>>` with those markers stripped from the input. Citations are built by `PolicyQuestionService` from the `[n]` markers in the answer, dropping numbers outside the excerpt range. There is no silent BM25-only fallback: a missing embedding host or empty index is a 503 (`PolicySearchNotConfigured/Unavailable`, `PoliciesNotIndexed` in `GlobalExceptionHandler`).
- To add a policy: put a Markdown file in `policies/` (`# Title`, `##` sections) and call `POST /policies/reindex`. Changing the embedding model re-embeds everything; a different vector size needs the Qdrant collection deleted.
- Config is the `Policies` section (`Embedding`, `Qdrant`, `Chunking`, `Retrieval`); the Ollama URL and Qdrant key come from `.env` (`Policies__Embedding__Endpoint`, `Policies__Qdrant__ApiKey`). Never log the question, answer or policy text.
- Tests: unit tests use `FakePolicyEmbedder`, `InMemoryPolicyVectorStore`, `FakePolicyLoader` and `StubApiServer` (for the Ollama embedder). `IntegrationTests/Qdrant` runs the real store against a Testcontainers `qdrant/qdrant` container (`QdrantFixture`). API tests use the real policy services by default; `ApiFactory.WithFakePolicies()` swaps in the scriptable `ApiFactory.Policies`.

## Tests

- Unit tests do no external I/O; services run against in-memory fakes in `tests/OrderManagement.UnitTests/Fakes`. The provider adapter tests are the exception: they use a loopback HTTP stub (`StubApiServer`).
- Integration tests: `ApiFactory` (a `WebApplicationFactory<Program>`) runs the API in the `Testing` environment against a Testcontainers `mysql:8.4` container (`MySqlFixture`) shared by the `Api` collection. `IntegrationTestBase` empties the tables and re-seeds before every test, so tests must not depend on each other. New API test classes derive from it and take `ApiFactory`; `TestClient` has helpers for registering, logging in and creating data.
- Development is test-first.
