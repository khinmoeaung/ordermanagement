# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- Build: `dotnet build`
- Run the API: `dotnet run --project src/OrderManagement.Api` (needs MySQL and user-secrets, see README)
- Docker stack: `docker compose up --build` (copy `.env.example` to `.env` first)
- All tests: `dotnet test` (integration tests need Docker running)
- One test: `dotnet test --project tests/OrderManagement.UnitTests --filter "FullyQualifiedName~<Name>"`. The runner is Microsoft.Testing.Platform (`global.json`); without `--project`, a project with no match makes the run exit with code 8.
- Regenerate the EF model after a schema change: `scripts/scaffold.ps1` (needs Docker and the local `dotnet-ef` tool).
- On an old Docker Engine (20.10), integration tests need `DOCKER_API_VERSION=1.41` in the environment. Never commit that setting.

## Architecture

.NET 10. `src/` has Domain, Application, Infrastructure and Api; `tests/` has UnitTests and IntegrationTests.

- Dependencies point inwards: `Api -> Application, Infrastructure`; `Infrastructure -> Application, Domain`; `Application -> Domain`. Domain has no package references and never reads the clock (time arrives as `DateTime utcNow`).
- Application holds services, DTOs, FluentValidation validators and the interfaces (repositories, `IUnitOfWork`, `ICurrentUser`). Infrastructure implements them with EF Core (`MySql.EntityFrameworkCore`), DbUp, JWT and the password hasher.
- Package versions are central in `Directory.Packages.props`. No AutoMapper, MediatR or FluentAssertions (licensing); mapping is by hand.
- Config keys: `ConnectionStrings:Default`, `Jwt:*` (signing key at least 32 bytes), `Seed:*`. Secrets come from user-secrets (Development) or `.env` (Docker); `appsettings.json` holds none. `Program.cs` runs DbUp and the seeder only in `Development` and `Docker`; the `Testing` environment leaves that to the tests.

## Database-first rules

- SQL scripts in `database/migrations/NNNN_*.sql` are the source of truth. Never edit a committed script; add a new one.
- Entities and `AppDbContext` are generated (they carry an `<auto-generated>` header). Never hand-edit them; run `scripts/scaffold.ps1`. The customized templates are in `Infrastructure/CodeTemplates/EFCore`.
- Business rules go in `<Entity>.Behavior.cs` partials. Services change entities only through behavior methods, never by setting generated properties. `AppDbContext.Partial.cs` holds the concurrency token (`Product.StockQuantity`) and `IUnitOfWork`.
- A new table must also be added to the `--table` list in `scripts/scaffold.ps1`, or it is silently left out of the model.
- Commit a new script and the regenerated code together.
- IDs are `Guid.CreateVersion7()`, money is `decimal(18,2)`, times are UTC.

## Error handling

`GlobalExceptionHandler` turns exceptions into RFC 9457 ProblemDetails with a `traceId`:

- validation failures (from `ValidationFilter`): 400 with per-field `errors`
- `NotFoundException`: 404; `ConflictException`: 409 (Infrastructure maps `DbUpdateConcurrencyException` and MySQL duplicate key 1062 to it)
- any other `DomainException`: 400
- anything else: 500 with a generic message

Empty 401/403/404 responses also become ProblemDetails through `UseStatusCodePages`. A customer asking for another customer's order gets 404, not 403.

## Assistant (Claude tool calling)

- `POST /api/v1/assistant/chat` (CustomerOnly). The loop and the gate are in `Application/Assistant` (`AssistantService`, `ToolExecutor`, `Tools/`). The Anthropic SDK is used only in `Infrastructure/Assistant/AnthropicAssistantModel.cs`, behind `IAssistantModel`.
- Model input is untrusted. Tools take no user ID, customer ID or role. They call services that read the caller from `ICurrentUser`, and every call goes through `ToolExecutor` (allowlist, then strict input validation, then a restricted DTO). Never return entities or full response DTOs to the model.
- To add a tool: implement `IAssistantTool` with a JSON schema (`additionalProperties: false`), validate the input with `ToolInput`, return a small result record, register it in `AddApplication()`, and add unit tests plus a cross-customer integration test.
- The API key comes from the `ANTHROPIC_API_KEY` configuration key. When it's missing, the endpoint returns 503. Settings are in the `Assistant` section.
- Tests never call Claude. Unit tests use `FakeAssistantModel`, adapter tests use `StubAnthropicServer`, and API tests script `ApiFactory.Assistant` (`ScriptedAssistantModel`).

## Tests

- Unit tests do no I/O; services run against in-memory fakes in `tests/OrderManagement.UnitTests/Fakes`.
- Integration tests: `ApiFactory` (a `WebApplicationFactory<Program>`) runs the API in the `Testing` environment against a Testcontainers `mysql:8.4` container (`MySqlFixture`) shared by the `Api` collection. `IntegrationTestBase` empties the tables and re-seeds before every test, so tests must not depend on each other. New API test classes derive from it and take `ApiFactory`; `TestClient` has helpers for registering, logging in and creating data.
- Development is test-first.
