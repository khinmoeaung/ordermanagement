# OrderManagement Core API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a .NET 10 layered-monolith REST API for order management with JWT access and refresh tokens, Admin and Customer roles, products, customers and orders with a status workflow and stock control, on MySQL 8.4.

**Architecture:** Four projects, Domain ← Application ← Infrastructure ← Api. Database-first: numbered SQL scripts are the schema's source of truth, DbUp applies them, and `dotnet ef dbcontext scaffold` generates the entity classes (into Domain) and `AppDbContext` (into Infrastructure). Hand-written `*.Behavior.cs` partials add the business rules to the generated entities. Application services coordinate repositories through interfaces. Api holds thin controllers plus cross-cutting concerns (JWT, ProblemDetails, validation filter, Swagger, Serilog).

**Tech Stack:** .NET 10 / ASP.NET Core, EF Core 10.0.12 + MySql.EntityFrameworkCore 10.0.12, DbUp (dbup-mysql 6.1.0), FluentValidation 12.2.0, Serilog.AspNetCore 10.0.0, Swashbuckle.AspNetCore 10.3.1, xunit.v3 4.0.2, Shouldly 4.3.0, Testcontainers.MySql 4.16.0, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-10-23-ordermanagement-core-api-design.md`. Read it alongside this plan: section numbers below (§N) refer to it.

## Global Constraints

- Target `net10.0` for every project. SDK installed: 10.0.402.
- Central package versions in `Directory.Packages.props`:
  - `Microsoft.EntityFrameworkCore`, `.Relational`, `.Design` = **10.0.12** (must match the provider's dependency)
  - `MySql.EntityFrameworkCore` = **10.0.12**
  - `Microsoft.AspNetCore.Authentication.JwtBearer`, `Microsoft.AspNetCore.Mvc.Testing`, `Microsoft.Extensions.Identity.Core` = **10.0.13**
  - `Microsoft.Extensions.TimeProvider.Testing` = the latest stable **10.0.x**
  - `FluentValidation`, `FluentValidation.DependencyInjectionExtensions` = **12.2.0**
  - `Serilog.AspNetCore` = **10.0.0**
  - `Swashbuckle.AspNetCore` = **10.3.1**
  - `xunit.v3` = **4.0.2**, `xunit.runner.visualstudio` = **4.0.1**, `Microsoft.NET.Test.Sdk` = **18.11.0**
  - `Shouldly` = **4.3.0**, `Testcontainers.MySql` = **4.16.0**
  - `dbup-mysql` = **6.1.0**
- `Directory.Build.props`: `Nullable=enable`, `ImplicitUsings=enable`, `TreatWarningsAsErrors=true`, `LangVersion=latest`.
- No AutoMapper, MediatR or FluentAssertions (all commercial licenses). Map by hand with extension methods.
- Domain has no package references. It never reads the clock: the current time comes in as `DateTime utcNow`.
- **Database-first (spec §2a):** never hand-edit a generated file (they carry an `<auto-generated>` header). A schema change is a new `database/migrations/NNNN_*.sql` script followed by `scripts/scaffold.ps1`, with the script and the regenerated code committed together. Business rules go in `<Entity>.Behavior.cs` partials. Services change entities only through those behavior methods, never by setting generated properties directly.
- IDs: `Guid.CreateVersion7()`. Money: `decimal(18,2)`. All times UTC.
- Routes are under `/api/v1`. Enums are serialized as strings. Every error response is RFC 9457 ProblemDetails with a `traceId`.
- **Commits:** one description line only, with no prefixes like `feat:` and no trailers. Work on branch `feature/core-api-init`.
- Integration tests need Docker running.

## Review Focus

1. **Malformed JSON body** (for example `{"email":`) must return a 400 ProblemDetails response, not a 500. The test is in Task 11.
2. **Email case and whitespace:** registering ` Bob@Example.com ` and then logging in as `bob@example.com` must work, and registering `BOB@example.com` afterwards must return 409. Tests are in Task 7.
3. **Cancelling an order whose product has since been deactivated** must still restore that product's stock. The test is in Task 9.
4. **Prices with more than 2 decimal places** (`19.999`) must be rejected with 400, not silently rounded. The test is in Task 6.
5. **Bad route or query values:** a non-GUID ID (`/orders/abc`) must return 404 and an unknown status (`?status=Foo`) must return 400, not 500. Tests are in Task 13.
